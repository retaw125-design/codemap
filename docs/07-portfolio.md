## 테스트 전략
| 종류 | 대상 | 방법 |
|---|---|---|
| 단위 | 영향 범위, 레이어 판정, 이름 변경 판정, 위치 채점 | 순수 함수, 공용 케이스는 양쪽 실행 |
| 통합 | 분석 파이프라인 | 삼선뉴스 + 오픈소스 2개의 결과가 정답 그래프와 일치 |
| 통합 | 작업 큐 | 두 작업자가 같은 작업을 동시에 가져가지 못함 |
| E2E | 핵심 흐름 | 로그인 → 주소 입력 → 지도 → 클릭 → 빛 → 편집 → 반영 → 문제 풀기 |
| AI 평가 | 채점, 문제 생성 | 평가셋 기반 점수 스크립트. 프롬프트·모델 변경 시마다 실행 |

LLM은 같은 입력에도 답이 달라지므로 일반 테스트가 아니라 평가셋으로 검증한다.

## 남길 수치
- LLM 채점과 사람 채점의 일치율
- mini 대 nano: 비용과 일치율
- AI가 지어낸 정답을 규칙으로 걸러낸 비율
- 편집 후 지도 반영 시간
- 저장소 크기별 분석 시간
- 요청당 LLM 비용, 캐시 적중률

개선 전후 비교 후보: 분석 작업을 API와 같은 공간에서 돌릴 때와 분리했을 때, 분석 중 다른 요청의 응답 시간.

## 면접 예상 질문
| 질문 | 답변 요지 |
|---|---|
| 왜 만들었어요? | 팀 프로젝트에서 영향 범위를 몰라 불안했던 경험. 설명 도구는 많지만 직접 맞히고 채점받는 훈련 도구는 없었다 |
| 왜 Vite예요? | 검색 노출이 필요 없는 도구형 앱이라 서버 렌더링이 필요 없었다 |
| 왜 Redis를 안 썼어요? | 월 $5 제약 안에서 서비스 수를 줄이려고 Postgres로 큐를 만들었다. SKIP LOCKED와 임대 만료로 안전하게 처리한다 |
| 서버와 브라우저 결과가 다르면요? | 추출 규칙을 쿼리 파일로 공유하고 같은 테스트 케이스로 검증했다 |
| LLM 채점을 어떻게 믿어요? | 위치는 규칙, 이유만 LLM으로 나눴고 사람 평가셋과의 일치율을 측정했다 |
| OpenAI 장애 시? | 규칙 기능은 계속 동작하고 차단기로 AI 기능만 끈다 |
| 남의 저장소가 위험하지 않아요? | 실행하지 않고, 크기를 먼저 확인하고, 링크를 따라가지 않는다 |
| AI로 개발했어요? | 에이전트 팀을 썼지만 설계 결정과 머지 승인은 직접 했고, 이해 못 한 코드는 합치지 않았다. 같은 명세의 결과물을 이 도구로 비교했다 |
| 가장 어려웠던 건? | 만든 뒤에 채운다 (예상: 편집 후 같은 함수 판별) |
